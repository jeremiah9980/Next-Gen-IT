1.1 — How a website actually works
30 min · whiteboard, no computers
▶

The three things a client is buying:

  1. A domain — the name. Rented yearly. (Cloudflare Registrar)
  2. Hosting — the computer that hands out the files. (GitHub Pages)
  3. The site — the files themselves. (Built with AI, stored in GitHub)
customer types → joesbarbershop.com │ ▼ DNS lookup (Cloudflare) "what's the address for this name?" │ returns an IP ▼ Web host (GitHub Pages) "give me the files" │ serves index.html, css, images ▼ browser renders the page
Teaching checkIf a client says "my website is down," name the three places you look: DNS, hosting, the files. If you can answer that, 1.1 is done.

1.2 — GitHub from zero
45 min · hands‑on, your machine
▶
  1. Create the GitHub account. Professional username — it shows up in client URLs.
  2. Turn on 2FA immediately. Non‑negotiable. This account will hold client property.
  3. Create a repo: test-site. Public. Add a README.
  4. Edit the README in the browser. Commit. Look at the commit history.
  5. Break something on purpose. Delete half the README, commit, then revert the commit.
The mental modelGitHub is not "for programmers." It's a filing cabinet that remembers every version of every file and never loses anything. Nothing you do is permanent — that's the whole point of step 5.
✓
1.3 — GitHub Pages: first site live
30 min · your first live URL
▶

In test-site, create index.html:

<!DOCTYPE html> <html> <head><title>It works</title></head> <body><h1>Myles was here</h1></body> </html>

Then: Settings → Pages → Source: Deploy from a branch → main / root → Save. Wait ~60 seconds. Visit https://<username>.github.io/test-site/.

Stop hereYou now have a live website on the internet. Let that land. Then change the <h1>, commit, refresh — edit → commit → live is the entire loop.

2.1 — Three ways to get AI code into GitHub
learn on #1, earn on #2 and #3
▶

Method 1 — Copy/paste (start here). Prompt the AI → copy the HTML → paste into GitHub's web editor → commit. Slow, zero setup, you see every step. Use for your first two sites.

Method 2 — AI connected to the repo. Claude and ChatGPT can both connect to GitHub and propose changes directly. Then you ask in plain English: "In the joes‑barbershop repo, update the hours — closed Mondays, open til 7 Fridays."

Method 3 — Local clone + agentic coding tool. Clone the repo, let the tool edit files and push. Fastest for real work. Session‑3+ skill.

Access ruleGrant the AI access to only the specific repos it needs — never blanket "all repositories" on an account holding client work. And verify connector setup steps in the live docs; they change often.
✓
2.2 — Prompting for websites (the part people get wrong)
intake sheet → prompt skeleton → iterate
▶

Bad prompt: "Make me a website for a barbershop." → generic purple‑gradient template that looks like every AI site on earth.

Collect the intake sheet first:

  • Business name, tagline, what they do in the owner's words
  • Address, phone, email, hours
  • 5–10 real photos (phone photos beat stock — stock kills credibility)
  • Services + prices · social links · Google Business link
  • 2–3 real reviews to quote
  • Two competitor sites they like, two they hate, and why
  • Existing logo/colors if any

Prompt skeleton to memorize:

Build a single-file index.html for [BUSINESS], a [TYPE] in [CITY]. Audience: [who walks in the door] Goal: get visitors to [call / book / visit] Sections, in order: hero with tagline + big call button services with prices about (use this copy: "...") gallery placeholders for 6 photos reviews (3 quoted below) hours + address + embedded map link footer with phone, email, socials Style: [e.g. "dark, industrial, heavy sans-serif — think motorcycle shop, not tech startup"]. Not generic. No purple gradients. No lorem ipsum — use the real copy below. Requirements: - single self-contained HTML file, inline CSS - mobile-first, must look right on a phone - click-to-call links (tel:) on every phone number - semantic HTML, alt text on images - loads fast, no heavy frameworks Real content: [paste the intake sheet]
Then iterate — never accept draft one"Hero too tall on mobile, cut to 60vh." · "Make the call button sticky at the bottom on phones." · "Gold's too yellow, go more brass."

Session 03Domains, DNS & delivery
~2 hours · hands‑on
✓
3.1 — Cloudflare account + domain
30 min
▶
  1. Create Cloudflare account, enable 2FA.
  2. Register the domain through Cloudflare Registrar — at‑cost pricing, no first‑year bait, no renewal gouging.
  3. If the client already owns a domain elsewhere: transfer it in, or just point its nameservers at Cloudflare (faster, less scary for the client).
Client‑ownership rule — ethics, not just processThe domain is registered in the CLIENT's name, ideally their own account with you added as a user. Holding a client's domain hostage builds a reputation you can't outrun. Put it in writing: "You own your domain. I manage it for you."
✓
3.2 — Pointing a domain at GitHub Pages
45 min · includes the gotcha that eats afternoons
▶

In the repo: Settings → Pages → Custom domain → enter the domain → Save (creates a CNAME file).

In Cloudflare DNS, add:

TypeNameValue
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
CNAMEwww<username>.github.io
Verify before every deployCheck these IPs against GitHub's current Pages docs — they've changed before and will change again. Never teach an IP as permanent truth.
The Cloudflare proxy gotchaOrange‑cloud proxy + GitHub Pages certs can cause redirect loops. Safe sequence: (1) set records to DNS only (grey cloud) first → (2) wait for GitHub to issue the cert, check Enforce HTTPS → (3) only then flip the proxy on, with SSL/TLS mode Full or Full (strict) — never "Flexible." Flexible = infinite redirect loop.

Debugging drill — break it live, then fix it:

  • Delete one A record → observe.
  • Set SSL mode to Flexible → watch the loop → fix it.
  • dig domain.com and nslookup to prove where a problem lives.

Propagation reality: usually minutes on Cloudflare — but tell clients "up to 24 hours" so you're never the one who was wrong.
